# المخطط الهندسي الشامل لتطبيق ونس AI

> تاريخ المراجعة: 6 نوفمبر 2026  
> المستودع: `naslok3-blip/wens-ai-backend`  
> هذا الملف هو مرجع التنفيذ والاختبار. لا تُعتبر أي ميزة مكتملة لمجرد وجود كود لها؛ يلزم اختبارها على النسخة المنشورة والهاتف.

## 1. الرؤية وحدود المنتج

ونس AI تطبيق ويب تقدمي (PWA) عربي باتجاه RTL، يعمل على هواتف Android وiPhone، مع خادم Cloudflare Worker وقاعدة D1، وواجهة مالك داخل التطبيق نفسه. التجربة الأساسية هي محادثة كاملة الشاشة مع شخصية ونس، نص وصوت وملفات وصور، وأدوات وكيل تنفذ المهام المسموح بها وتعرض النتيجة في المحادثة نفسها.

**قرار الإصدار المجاني الحالي:** لا توجد مكالمات فيديو حية مكتملة، ولا يجب عرض زر فيديو على أنه يعمل. الأولوية للمحادثة النصية، الصوت المحلي المتاح على الجهاز، الوكيل، لوحة المالك، الاعتمادية والأمان. يمكن تقييم الفيديو لاحقًا فقط إذا توفر مسار مجاني مستقر وحقوق استخدام واضحة.

## 2. خريطة النظام من الخارج إلى الداخل

```
الهاتف / المتصفح
  ├─ واجهة Wens PWA (HTML/CSS/JS)
  │   ├─ تسجيل الدخول والجلسات
  │   ├─ شاشة المحادثة والملفات
  │   ├─ مشغل الصوت والميكروفون
  │   └─ مدخل المالك المخفي → لوحة الإدارة داخل الصفحة
  │
  └─ HTTPS API
      └─ Cloudflare Worker
          ├─ Auth & Session Service
          ├─ Chat / Agent Orchestrator
          ├─ Tools: web, browser, tasks, image, documents
          ├─ Realtime Voice Gateway
          ├─ Owner/Admin API
          ├─ Settings & Feature Flags
          └─ Health, diagnostics, logs
                │
                ├─ D1: users / sessions / messages / settings / tasks
                ├─ Workers AI: الردود والوكيل
                ├─ OpenAI API: Realtime والصور/الملفات حسب التهيئة
                └─ Browser binding: تصفح المواقع المصرح بها
```

### حدود المسؤولية

| الطبقة | مسؤوليتها | ممنوع أن تفعله |
|---|---|---|
| الواجهة | عرض الحالة، جمع مدخلات المستخدم، رفع المرفقات، عرض نتائج الأدوات | تخزين مفاتيح API أو اتخاذ قرار صلاحيات أمني |
| Worker | التحقق من الهوية، قواعد العمل، تنفيذ الأدوات، حماية الأسرار، حفظ البيانات | الثقة في صلاحية يرسلها المتصفح من تلقاء نفسه |
| D1 | الحسابات والجلسات والرسائل والإعدادات والمهام وسجل التدقيق | تخزين مفاتيح الخدمة كنص مكشوف |
| لوحة المالك | تعديل إعدادات التطبيق العامة وقيود الميزات ومراقبة الخدمات | تجاوز التحقق من المالك أو إظهار الأسرار |
| مزودو الذكاء الاصطناعي | الاستدلال والصوت ومعالجة الصور/المستندات | الوصول المباشر إلى حساب المستخدم أو أسراره |

## 3. التصميم الخارجي وتجربة الاستخدام

### شاشة المحادثة على الهاتف

- ارتفاع الشاشة الفعلي باستخدام `100dvh` مع احترام شريط الحالة والـ safe areas في Android وiOS.
- شريط علوي ثابت وصغير، وصورة ونس وهوية مختصرة.
- سجل الرسائل هو المساحة الرئيسية المرنة؛ التمرير يكون داخله فقط، وليس الصفحة كلها.
- شريط كتابة ثابت أسفل الشاشة مع زر الإرسال والمرفقات والميكروفون.
- القوائم المنبثقة تظهر فوق المحتوى ولا تدفع الشاشة أو تغيّر ارتفاعها.
- كل عنصر له حالات تحميل وتعطيل وخطأ ونجاح واضحة؛ لا تختفي الرسالة عند فشل الإرسال.
- شاشة الدخول، المحادثة، لوحة المالك، ومعاينة الصورة تتبع نظام ألوان وخطوط ومسافات موحدًا.

### معايير التصميم

- RTL صحيح، دعم عرض 320–430px، وتخطيطات منفصلة للشاشات الكبيرة.
- أحجام لمس مناسبة، تباين واضح، حالات focus، ودعم قارئ الشاشة.
- عدم تثبيت ارتفاعات قد تقص المحتوى عند ظهور لوحة مفاتيح الهاتف.
- منع التمرير المزدوج: منطقة رسائل واحدة قابلة للتمرير، وحاوية الإدارة لها تمرير داخلي مستقل.
- عدم عرض زر فيديو أو عناصر غير مستخدمة في نطاق المنتج الحالي.

## 4. التصميم الداخلي والخدمات

### تسجيل الدخول والبيانات

- جلسات عادية HttpOnly + Secure + SameSite، ورموز مخزنة في D1 على هيئة hashes فقط.
- فصل جلسة المستخدم عن جلسة المدير، مع انتهاء تلقائي وإبطال عند الخروج.
- حماية محاولات الدخول على مستوى مركزي قابل للتوسع، لا على ذاكرة Worker المؤقتة وحدها.
- تحقق من ملكية الحساب قبل إعداد كلمة مرور المدير أو إعادة ضبطها.
- migrations مرقمة وقابلة لإعادة التطبيق بأمان، مع فحص مخطط D1 الحقيقي.

### خدمة المحادثة والوكيل

- مسار واحد واضح للمحادثة، مع سجل موحد للرسائل وخطوات التنفيذ.
- كل أداة لها: اسم، وصف، مخطط مدخلات، تحقق خادمي، صلاحية مطلوبة، حد زمني، حد حجم، ورسالة نتيجة.
- الوكيل لا يدّعي تنفيذ مهمة خارجية إلا عند تلقي نتيجة فعلية من الأداة.
- العمليات المؤثرة (إرسال، شراء، حذف، نشر، دخول حسابات) تتطلب سياسة تأكيد مناسبة؛ لا تُستخدم عبارة «نفذت» قبل النجاح.
- نتائج الأدوات تظهر أسفل رد ونس في نفس فقاعة/مجرى المحادثة، مع سجل خطوات مختصر قابل للفتح.
- حماية من prompt injection في صفحات الويب والملفات: المحتوى المسترجع بيانات لا تعليمات نظام.

### الملفات والصور

- أنواع الملفات المعلنة تطابق الأنواع المدعومة فعليًا؛ غير المدعوم يظهر بوضوح أنه اسم ملف فقط.
- التحقق من MIME والامتداد والحجم على الخادم، وليس المتصفح فقط.
- استخراج مجاني محلي للنص من PDF الذي يحتوي على طبقة نصية وDOCX وXLSX وPPTX عبر document-utils.mjs؛ الحد 8 MiB للملف و4 MiB للمحتوى بعد فك الضغط. لا يوجد OCR للملفات المصوّرة، ولا دعم للصيغ القديمة DOC/XLS/PPT دون تحويل. تُمرر النصوص المستخرجة إلى Workers AI للفهم، ويجب مقارنة مقتطف الاستخراج بالأصل.
- الصور تُضغط محليًا، وتبقى نسخة أصلية/معاينة واضحة للمستخدم، وتظهر الصور المنشأة أو المعدّلة داخل المحادثة.
- تخزين الملفات الكبيرة مستقبلًا في R2 مع بيانات وصفية في D1 بدل تضخيم صف إعدادات التطبيق.

### الصوت والنطق

- مسار مجاني افتراضي: التعرف على الكلام والنطق عبر إمكانات الجهاز/المتصفح مع تفضيل ar-EG واختيار صوت عربي مثبت إن توفر. جودة اللهجة المصرية والجنس الصوتي تختلف من جهاز لآخر ولا تُضمن برمجيًا.
- يوجد مسار Realtime عبر WebRTC في الخادم، لكنه يعتمد على OPENAI_API_KEY وقد يستهلك رصيدًا؛ لذلك ليس جزءًا من الوضع المجاني ولا يُعلن أنه يعمل دون اختبار سماع فعلي.
- مشغل صوت ظاهر داخل الرد نفسه، مع إعادة تشغيل الرد السابق.
- إعداد مركزي اختياري للتشغيل التلقائي لردود ونس، مع إبقاء زر التشغيل اليدوي دائمًا كبديل عند منع المتصفح التشغيل التلقائي.
- لا نعلن «الصوت المصري الطبيعي يعمل» بناءً على تعيين اللغة فقط؛ نحتاج سماعًا فعليًا على هاتف المستخدم. عند غياب صوت مصري مثبت يجب توضيح أن الموجود صوت عربي بديل.

## 5. لوحة المالك: مركز تحكم حقيقي

مدخلها يبقى مخفيًا بالضغط خمس مرات على صورة ونس، لكن الحماية الحقيقية من الخادم. لوحة المالك تستخدم كلمة مرور مستقلة، وجلسة منفصلة، ومحدودية للمحاولات، ولا تخلط صلاحية المدير بحساب المستخدم العادي.

### أقسام الإدارة المطلوبة

| القسم | عناصر التحكم |
|---|---|
| نظرة عامة | حالة Worker وD1 وWorkers AI وRealtime وBrowser، آخر فحص، أخطاء التشغيل |
| هوية التطبيق | الاسم، وصف ونس، الصورة، الألوان، شعار التطبيق، بيانات PWA |
| المحادثة | رسالة البداية، قواعد النبرة، طول الرد، نصوص الواجهة |
| الصوت | الصوت/النبرة، التشغيل التلقائي، تفعيل الميكروفون، اختبار الاتصال الفعلي |
| الميزات | تشغيل/إيقاف البحث، المتصفح، المهام، توليد الصور، قراءة الملفات، التفكير الأعمق |
| الوكيل | الأدوات المتاحة، حدود التنفيذ، المواقع المسموحة، حدود الوقت والحجم |
| المستخدمون | عدد الحسابات، حظر/إلغاء حظر، إنهاء الجلسات، دون كشف كلمات المرور |
| البيانات | عدد الرسائل والمهام، الاحتفاظ، التصدير، النسخ الاحتياطي والاسترجاع الآمن |
| الأمان | تغيير كلمة مرور المدير، الجلسات النشطة، محاولات الدخول، سجل الإجراءات |
| النسخ والإصدارات | تصدير إعدادات JSON، استرجاعها مع تحقق، رقم إصدار الواجهة والخادم |

كل إعداد يؤثر على كل المستخدمين يجب أن يُقرأ ويُحفظ على الخادم، لا في `localStorage`. ولا يمكن للوحة تعديل مفاتيح API نفسها؛ إدارة الأسرار تتم من Cloudflare Secrets.


## 6 مكرر. الذاكرة والميزات الشخصية

- توجد ذاكرة خاصة لكل مستخدم، مع أدوات حفظ وعرض وحذف.
- لا تُحفظ أي معلومة إلا بطلب صريح من المستخدم؛ الحد 30 معلومة، وكل معلومة حتى 500 حرف.
- تمنع السياسة حفظ كلمات المرور ومفاتيح API وبيانات الدفع والبيانات الصحية والدينية والسياسية والجنسية وبيانات الهوية والعناوين الخاصة.
- يتم تحميل آخر 20 تفضيلًا/اهتمامًا/تفصيل مشروع غير حساس إلى سياق المستخدم نفسه، ولا تُشارك بين الحسابات.
- الذاكرة ليست سجل ملفات ولا بديلًا عن موافقة المستخدم أو سياسة الاحتفاظ بالبيانات.

## 7. الأمان والاعتمادية

- عدم وضع الأسرار في GitHub أو HTML أو JavaScript المنشور.
- التحقق من المالك على الخادم في كل endpoint إداري، وليس إخفاء عناصر الواجهة فقط.
- تحديد المعدل والحجم والوقت على نقاط الدخول الحساسة.
- CORS مقيد بالأصل المتوقع عند الحاجة، ورفض الطلبات غير المتوقعة.
- CSP وقيود فتح الروابط الخارجية و`noopener noreferrer`.
- سجل تدقيق للإجراءات الإدارية دون كلمات مرور أو محتوى محادثات خاص.
- استثناء `/api/*` من Cache، وتحديث نسخة Service Worker عند كل إصدار لتفادي بقاء ملفات قديمة.
- فحص فشل D1 وWorkers AI وOpenAI منفصلًا حتى لا يظهر التطبيق «جاهزًا» لمجرد وجود Binding.
- مراقبة أخطاء Worker مع request IDs لا تحتوي على مفاتيح أو بيانات حساسة.

| P2 — الصوت | جلسة Realtime، تشغيل وإعادة تشغيل، اختيار النبرة، وضع تلقائي اختياري | سماع صوت فعلي على هاتفين/متصفحين مختلفين |
| P3 — الوكيل | عقود الأدوات، نتائج حقيقية، منع ادعاء التنفيذ، ضوابط مواقع ومهام | اختبارات لكل أداة ناجحة وفاشلة |
| P4 — المستندات والصور | اختبار ملفات حقيقية PDF/DOCX/XLSX/PPTX وصور | التحقق من النتائج والمرفقات والحدود والأخطاء |

| P6 — الإطلاق | اختبارات أمنية، اختبار ضغط معتدل، مراقبة، PWA، SEO، نسخة إصدار | قائمة قبول كاملة واجتياز Smoke/E2E |

## 9. مصفوفة الاختبار الإلزامية

1. الدخول، إنشاء حساب، تسجيل خروج، انتهاء الجلسة، رفض حساب غير مالك.
2. إرسال رسالة قصيرة وطويلة، انقطاع الإنترنت، إعادة المحاولة، واسترجاع سجل المحادثة.
3. صورة JPG/PNG/WebP، ملف كبير، نوع غير مدعوم، وصورة مولدة/معدّلة.
4. PDF نصي وممسوح ضوئيًا، DOCX، XLSX متعدد الأوراق، وملف تالف.
5. تسجيل الميكروفون مع منح/رفض الصلاحية، نطق رد، إيقاف الصوت، إعادة التشغيل، منع autoplay.
6. استخدام كل أداة وكيل مع نتيجة نجاح وفشل ومهلة زمنية وحدود صلاحية.
7. فتح لوحة المالك من داخل التطبيق، رفض غير المالك، إعداد/تغيير كلمة مرور المدير، حفظ/استرجاع صورة وإعدادات.
8. فتح نفس الحساب من هاتفين، والتحقق من أن الإعدادات المركزية تظهر على كليهما.
9. اختبار الواجهة على شاشات صغيرة وكبيرة، لوحة المفاتيح، الوضع الرأسي، وتدوير الجهاز.
10. اختبار عدم تسرب الأسرار في Network/HTML/JS/Logs ورفض الطلبات الإدارية غير المصرح بها.

## 10. خط الأساس المرصود في 6 نوفمبر 2026

- المستودع يحتوي بالفعل على Worker وواجهة PWA ولوحة مالك وملفات Android ومخطط D1.
- إعداد Worker يربط `AI` و`DB` و`BROWSER` وسر OpenAI باسم `OPENAI_API_KEY`؛ وجود الربط لا يثبت صلاحية المفتاح أو نجاح الطلب.
- الاستعلام الفعلي على D1 أظهر جداول الحسابات والجلسات والرسائل والإعدادات والإدارة والمهام والمتصفح. توجد بيانات تشغيل فعلية؛ لذلك لا تُنفّذ إعادة تهيئة أو حذف بيانات أثناء الإصلاح.
- يوجد سجل إعداد عام، وبيانات حساب مالك، وبيانات جلسات ومحادثات. لم تُقرأ كلمات مرور أو محتويات رسائل المستخدمين أثناء هذا الفحص.
- كود الصوت يستخدم WebRTC وRealtime، لكنه يحتاج اختبار استماع حقيقي على الهاتف؛ فحص وجود المفتاح ليس اختبار صوت.
- واجهة الهاتف بها قواعد شاشة كاملة، لكن لوحة الإدارة المحمّلة داخل iframe تحتاج تمريرًا داخليًا مضبوطًا حتى لا تُقص أقسامها.
- توجد نسخ Assets داخل Worker إلى جانب ملفات `public/`؛ يجب أن تكون متطابقة ويجب أن يتحقق CI من ذلك.

## 11. تعريف «جاهز للإطلاق»

لا تُستخدم عبارة «جاهز» إلا بعد: نجاح فحوص البناء والتحقق من الملفات، صحة API وD1، اختبار تسجيل الدخول والمالك، إرسال رسالة والاحتفاظ بها، سماع صوت فعلي، قراءة ملفات حقيقية ومقارنة المحتوى، اختبار أداة وكيل من البداية للنهاية، حفظ واستعادة الإعدادات والصورة، اختبار الذاكرة الخاصة، واختبار الهاتف مع لوحة المفاتيح وPWA. اختبارات GitHub لا تثبت الصوت أو التثبيت أو تجربة المستخدم على هاتفه؛ كل جزء لم يختبر يظل معلّمًا «غير متحقق» بوضوح.
