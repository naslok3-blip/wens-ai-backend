# ونس AI — مشروع تطوير أندرويد وويب

ونس تطبيق مساعد ذكي بواجهة عربية، حسابات مستخدمين، سجل محادثات محفوظ، ومكالمات فيديو عبر LiveKit.

## الحالة التقنية

| الجزء | حالة الكود | ما يلزم لتشغيله فعليًا |
|---|---|---|
| تطبيق أندرويد APK | مشروع Android موجود + GitHub Actions للبناء | نجاح مهمة Android APK لتنزيل ملف APK |
| تسجيل الدخول | تسجيل/دخول/خروج وجلسة Cookie آمنة | ربط D1 وتطبيق migration |
| قاعدة البيانات | مخطط D1 للمستخدمين والجلسات والرسائل | إنشاء D1 وربطه باسم DB |
| مكالمات الفيديو | واجهة WebRTC + إصدار LiveKit JWT من الخادم | LiveKit URL وAPI key وAPI secret |
| الذكاء الاصطناعي | Cloudflare Workers AI عبر binding باسم AI | حصة مجانية يومية وحدود النموذج |

لا تعتبر الميزة متاحة لمجرد وجود كودها. افحص `GET /api/health` بعد النشر؛ سيعرض حالة Workers AI وقاعدة البيانات والفيديو كلٌّ على حدة.

## ملفات الواجهة المنشورة

Cloudflare Workers Assets يخدم المجلد `public/` فقط طبقًا لإعداد `wrangler.jsonc`. لذلك يجب أن تكون كل صفحات وملفات الواجهة العامة داخل هذا المجلد. صفحة الإعدادات `/admin.html` وملفاتها موجودة داخله أيضًا. عند تعديل `index.html` أو `app.js` أو `style.css` في جذر المشروع، حدّث النسخة المقابلة في `public/`؛ فحص الجودة يقارن النسختين.

لوحة `/admin.html` محمية بتسجيل دخول يتحقق منه الخادم عبر Secret، وتُفتح من التطبيق بالضغط على شعار ونس خمس مرات متتالية خلال 3 ثوانٍ (أو Ctrl+Shift+A على لوحة مفاتيح). جلسة المدير Cookie آمنة ومؤقتة. تخصيص الهوية والصوت ورسائل البداية يُحفظ محليًا على الجهاز الحالي؛ أما حالة الخدمات واختبار Workers AI فتُقرأ من الخادم. اللوحة لا تكشف المفاتيح ولا تدير أسرار الخادم.

## إعداد قاعدة البيانات D1 (لنسخة جديدة من المشروع)

قاعدة الإنتاج لهذا المشروع أُنشئت بالفعل باسم `wens-ai-db` وربطها موجود في `wrangler.jsonc`. عند إنشاء نسخة مستقلة من المستودع في حساب Cloudflare آخر، أنشئ قاعدة D1 جديدة باسم مناسب:

```bash
npx wrangler d1 create wens-ai-db
```

خذ `database_id` الذي يرجع من Cloudflare، ثم استبدل ربط `DB` في `wrangler.jsonc` بالمعرّف الجديد:

```jsonc
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "wens-ai-db",
    "database_id": "ضع-DATABASE-ID-الحقيقي-هنا",
    "migrations_dir": "migrations"
  }
]
```

طبّق الجداول على قاعدة الإنتاج:

```bash
npx wrangler d1 migrations apply wens-ai-db --remote
```

**لا تنشر إعداد D1 وفيه قيمة placeholder.** لا ترفع أي بيانات مستخدمين أو كلمات مرور إلى GitHub.

## إعدادات الإدارة

لا تحتاج لوحة الإدارة إلى أسرار إضافية. صلاحية المدير مرتبطة بحساب المالك الموجود مسبقًا في قاعدة D1، وتُنشأ له جلسة مؤقتة مدتها أربع ساعات بعد التحقق من كلمة المرور. لا تضع كلمات المرور في ملفات المستودع.

- `GET /api/admin/session` — فحص جلسة المدير.
- `POST /api/admin/login` — تسجيل دخول المالك بالبريد وكلمة مرور حساب ونس.
- `POST /api/admin/logout` — إنهاء جلسة المدير.
- `GET /api/admin/status` — حالة Workers AI وقاعدة البيانات.
- `POST /api/admin/test-ai` — اختبار نموذج Workers AI.
- `GET /api/settings` — تحميل إعدادات التطبيق العامة من D1.
- `GET /api/admin/settings` و`PUT /api/admin/settings` — قراءة وحفظ الإعدادات المركزية بعد التحقق من حساب المالك.

## بناء APK أندرويد

يوجد مشروع أندرويد داخل `android/` وسير عمل GitHub Actions داخل `.github/workflows/android-apk.yml`. عند دفع تحديثات في مجلد `android/` يبدأ بناء APK تلقائيًا، ويمكن تشغيله يدويًا من تبويب Actions.

بعد نجاح المهمة نزّل Artifact باسم `wens-android-apk`، ثم استخرج `app-debug.apk` وثبّته للاختبار. هذا Debug APK للتجربة الداخلية وليس إصدار متجر موقّعًا بمفتاح نشر نهائي.

## فحوص ما قبل النشر

1. تأكد أن `/api/health` يعرض `workersAI: true` و`database: true`. الفيديو سيظل `false` حتى إعداد LiveKit.
2. أنشئ حسابًا تجريبيًا، سجّل الخروج ثم الدخول، وافتح المحادثة من متصفح آخر للتأكد من حفظها.
3. جرّب مكالمة من جهازين مختلفين باستخدام نفس كود الغرفة.
4. اختبر رفض أذونات الكاميرا والميكروفون والتعامل مع انقطاع الشبكة.
5. لا تنشر نسخة عامة قبل سياسة خصوصية، شروط استخدام، حماية إساءة الاستخدام، ومراجعة إعدادات الاحتفاظ بالرسائل.

## النشر

إذا كان المستودع مربوطًا بـ Cloudflare Workers Builds، استخدم أمر النشر `npx wrangler deploy`. لا تضع أي مفتاح API داخل الواجهة أو داخل Git.
